🔴 The 4-reviewer convergence (highest confidence)

Runtime permission-freshness gap — perm_rev bumps on grant/revoke but nothing recompiles a running worker at runtime (only boot + Claim/Transfer re-sync). So a worker is either silently stalled (dispatch gate closes with no re-opener → session hangs) or silently wide (a revoked capability stays live in the on-disk config). Fix: on grant/revoke, fan out pause→recompile→resume to affected workers via the per-worker queue.

Blockers · fix before code
  • The freeze isn't frozen — the raw SQL block is stale rev-3; produce ONE 0001_init.sql, seed the pool row last, reconcile the "locked" Store/VMClient block, and define Deps (used everywhere, declared nowhere).
  • Redaction must be write-time — events is immutable, so an egress-only scrub leaves secrets on disk forever; add internal/redact before AppendEvent and before the brain prompt (the biggest exfil surface).
  • Quarantine + config-siting — repo .mcp.json/settings.local.json out-precede arco; and arco's own compiled config sits inside the worker-writable worktree. Stage it daemon-owned, outside the checkout.
  • Allowed() isn't authoritative over worker-direct calls — a worker curls the merge API in-process. Reframe: compiled config = prevention, arco = detection+response.
  • Worker LLM spend is never metered → budgets watch only the cheap brain; and provider-pool leases leak on crash.
  • Silent-drop kinds — final_output/handoff have no reconciler branch; herdr.Prompt isn't bracketed by intent/done.
Major · rev-4.2 crash windows (qwen)
  • Pending escalations aren't settled on transfer — a confirm yes decided after ownership moves authorizes under the new owner.
  • Release contradicts Pause on the worktree; the pool TTL reaper is a no-op with no durable clock.
  • Depth/fan-in caps unenforced at CreateSession — depth-3 is constructible today despite "deferred."
  • Authority laundering up the rollup — Tainted only persuades the LLM; make it structural.
  • Session teardown has no join (hangs active) and orphan worktrees are never GC'd.
  • Structural-liveness banners on Tasks 7/10/18; escalation timeout must close the row.

9 open questions genuinely need the maintainer (worker-spend observability, revoke-cascade vs ancestor-walk, exec-default-on posture, one-open-escalation semantics) — several gate a blocker and are decisions to confirm before PASS-0 is finalized.

🧠 Memory decision — "links, not a graph" (opus + fable + qwen3.8-max → unanimous SIMPLIFY)

The cross-project linking need is real (24a/b/c can't link an external OSS project to your project, nor record origin-provenance) — but a general typed node/graph is over-engineered and fights the frozen invariants: no edge author (the brain is banned from writing memory, B13), the ≤8KiB hot budget forbids multi-hop by construction, and a typed rel CHECK-enum would hit the PASS-0 freeze. Prior art agrees — mem0's flat store is the production default, Zep/Graphiti needs the banned always-on extraction pipeline, and Obsidian's durable "graph" is just [[links]] + a mechanical backlink index.

Ship it as a 24a increment: [[wikilinks]] in the existing topic files + a derived memory_links backlink index rebuilt at the mem_rev bump (md stays truth; the table has no write API); depth-1 retrieval via memory_read (multi-hop = the brain issuing another read, never engine traversal); OSS facts carry trust:external+Tainted; cross-scope recall behind a default-off memory.cross-project capability. Kill-criterion: if links aren't followed after ~4–8 weeks, delete the table — the wikilinks stay as inert prose, so rollback is zero-migration. Full design: docs/memory-links-rev5.md.

The shape (unchanged & endorsed)

  • Durable Go daemon + SQLite ledger owns the truth about every worker & session; survives restart.
  • The LLM brain is a short-lived guest — invoked per-event for a bounded decision, then exits. No long-running LLM process → no leaks, bounded cost, crash-safe.
  • Sessions are the first-class unit of work + conversation — a session owns a group of workers (across VMs), holds its own durable brain transcript, and carries a capability tree. Never a resident process.
  • Autonomy-first — routine actions never gate; a stuck worker asks a question, a dangerous action needs a confirm. Questions are answered two-level (arco's brain first, human only if uncertain or danger-class).
  • Least privilege — each session has a capability tree; workers inherit a narrowed copy; the operator widens with explicit grants.
  • Push is an optimization, not the truth — an authoritative periodic reconcile sweep repairs state even when events drop; intake is idempotent.

✅ All 3 model families agreed (high confidence — the must-fix backbone)

  • The permission compile is a courtesy lock, not a security boundary. Bash re-expresses any deny-listed command (sh -c, gh api, env indirection). FIX: keep it for accident-prevention/observability; make arco's own boundary check authoritative; never put high-blast capabilities on the worker at all. (Fable + Qwen)
  • Two-level autonomy is the single highest-risk piece (soft confidence threshold, no precedent). FIX: ship graduated — brain drafts, you one-tap approve first; auto-answer only later, per question-class, never for danger; per-session auto-answer budget; FYI-visible even when silent. (Fable "shadow mode first" + Qwen "graduate")
  • Danger-class must be assigned deterministically from the capability tree — never trust the worker's/brain's self-report. FIX: structural classifier; explicit test. (Fable dissent #2 + Qwen §2)
  • Standing grants must not accumulate forever. FIX: grant TTL + use-count aging (curator pattern), grants die with the session, weekly grants digest, [👀 diff] on confirms too. Keep high-blast CLI-only. (Fable + Qwen §3)
  • Telegram will hit rate limits at fleet scale (~20 msg/min per group, all topics). FIX: throttle status-card edits (≤1/topic/60s), buffered-vs-emitted policy, coalesce the General mirror too. (Fable dissent #3 + Qwen §4.4)

➕ Qwen added (Fable didn't emphasize — worth adopting)

  • The REAL trust boundary the plan never states: (1) no high-blast credentials on worker boxes (scoped per-session tokens); (2) server-side git branch protection / rulesets — the only non-advisory layer; (3) OS-user separation; (4) stage the compiled config outside the worker-writable worktree, read-only, and pin non-bypass permission mode (else a worker overwrites its own settings.json, or --dangerously-skip-permissions voids everything).
  • Cross-VM liveness is broken as written — Sweep/boot recovery use PID, meaningless off-host. Use herdr-reported liveness now (cheap today, a rewrite at P3 otherwise).
  • Delegation is default-ON, disagreeing with every teardown. Add max depth (start 1), per-session live-worker cap, spawn budget.
  • No fleet-level cost breaker — the billing ladder stops one worker; add a daily token/USD cap + per-session cap that parks new spawns.
  • Attention is the scarce resource — rule: anything that pages you must be actionable in <30s from a phone; default notify aggressive-silent + a daily digest.
  • Defer hindsight+curator (Task 24) past MVP — biggest surface (~2k lines); T1–T3 give ~90% of recall value. Build the compounding layer once there's something to compound.

✅ The five decisions — RESOLVED (you were away; my calls, change any)

  • Two-level autonomy → build the resolver but default to SHADOW/DRAFT in P2; auto-answer only after measured (≥50 samples, ≥95% agreement, 0 danger-misses); confirms never auto.
  • Worker self-spawn (delegation) → default OFF; per-session grant; depth 1; ≤2 children/parent; ≤5 live/session; ≤20 spawns/session/day.
  • Hindsight / curator / playbook-learning → deferred past MVP; P2 memory is manual-only (files + FTS5, capped, redacted).

  • Byte-stable transcript → keep the cheap invariant + prompt-hash + cache telemetry; no cache-plan engine until cache_read proves payoff.
