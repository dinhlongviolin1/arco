Section 01

The Original Plan

As frozen in the docs: a self-hosted Go daemon + SQLite ledger that supervises fleets of coding agents in tmux panes (herdr), launched with scoped credentials (clavis), with a cheap short-lived LLM "brain" invoked only on ambiguity. Rule #1: the ledger is the product — every side effect is intent→execute→result.

FROZENDesign Rules

  • Ledger-first. SQLite WAL, single writer, CAS revs, idempotent event intake (UNIQUE(source, source_event_id)).
  • Authoritative reconcile. Periodic sweep re-derives truth (liveness + git HEAD), never trusts cached state.
  • Cheap brain. Haiku-class, 120s timeout, called only on ambiguity; every call transcripted.
  • Capability tree. Grants compile onto worker settings.json (permcompile) + enforced again at the arco boundary.
  • Shadow-mode autonomy. Brain drafts escalation answers but is never authoritative in P2.

FROZENPromised Features

  • Sessions & workers with 11-state lifecycle (incl. lost, D-decision).
  • Two-level escalation (question / confirm), one pending per worker.
  • Diff-gated completion: completed_candidate → completed_verified.
  • 4-tier memory (facts, context summary, revisions, playbooks).
  • Provider pools + leases for rate-limit concurrency.
  • HMAC-SHA256 signed hook intake.
  • Cross-VM workers over SSH.
  • Cost tracking — CUT in §A

FROZENBuild Order (§D)

  • PASS-0 — freeze decisions, schema 0001_init.sql, Go contracts, pinned defaults.
  • PASS-1 — the spine: ledger, store, domain, reconcile skeleton, TDD with -race.
  • PASS-2 — single-VM walking skeleton: dispatch→clone→quarantine→permcompile→herdr launch→completion.
  • PASS-3 — hardening & security preconditions P1–P6, escalation plumbing, ops recovery.
  • Task S — de-risk spike: real LocalVMClient against real herdr.

Section 03

rev-7 — What Changes & Why

Full text in docs/plan-rev7.md. This revision came from a 3-round pass: reading herdr's actual source (HEAD 0.8.0), sweeping ~200 ecosystem plugins, red-teaming arco's own thesis, and source-auditing the competitor we found. Every decision below is badged: CHANGED = different from the earlier draft, NEW, PROMOTED, KEPT.

Why arco repositioned — the market in one picture

Your goal: drive agents manually in herdr at home; while away, supervise the 3-VM homelab from your phone; eventually only peek in. The tooling world splits into three layers:

LAYER 1
Remote control

A longer arm for your thumb — you still read everything and make every decision.

collie · herdr-remote · Anthropic Remote Control · Codex Remote
TAKEN — don't build
LAYER 2
Prompt answering

Unblocks the agent: approves permissions, answers menu questions. We found a direct competitor here — herdr-auto-pilot ("hap"), 1 month old, source-audited: its answering loop is genuinely mature. Anthropic's Auto Mode does permissions first-party.

hap · Claude Code Auto Mode
TAKEN — don't fight
LAYER 3
Outcome supervision

Proves the work actually got done: diff/test-verified completion, an audit ledger of who did what (you or the machine), across all machines, with the phone pinged only when judgment is needed. Source-verified: nobody does this — hap stops at "message delivered", never "work correct".

arco
EMPTY — arco's slot
IN PLAIN WORDSThe more layers 1–2 improve, the more work happens while nobody watches — which makes "prove it and keep receipts" more valuable over time, not less. That's the bet.
H2
D1 — SIGNALS CHANGED

Listen to herdr's push events; own hooks deferred

Build our own Claude Code hook wiring in H2→subscribe to herdr's documented socket event stream (events.subscribe); build our own hooks only if autonomy later needs them

Reading herdr's source settled it: herdr had hook-driven Claude state and deleted it in 0.6.7 because hooks made unreliable authority. Their docs explicitly invite external orchestrators to use the socket API instead.

IN PLAIN WORDSInstead of arco asking "anything new?" every 30 seconds, herdr now taps arco on the shoulder the moment an agent's state changes. And we don't build our own Claude wiretap until we actually need it.
H2
D2 — CONTAINMENT CHANGED

Use Anthropic's sandbox, not a bespoke one

Build our own bubblewrap + landlock wrapper + egress proxy→wrap agent launches with srt (anthropic-experimental/sandbox-runtime) + systemd-run limits as layer 2

srt is the thing we were going to build — bubblewrap isolation with all network egress forced through its allowlist proxy — already written and maintained by the vendor of the agents we're caging.

IN PLAIN WORDSAnthropic already built the cage. Use theirs, add systemd's free locks on top, and delete a whole bespoke subsystem from the plan.
H1→H3
D3 — IDENTITY KEPT

Fix who's allowed to report events

Local: bind events to the worker's UID via SO_PEERCRED (H1). Cross-VM: per-worker derived HMAC keys (HKDF) + replay guards (H3). Remove the workspace-name fallback that lets any key holder forge any worker's events.

IN PLAIN WORDSRight now, one leaked key lets anyone impersonate any worker. After this, each worker can only speak as itself.
H3
D4 — EVIDENCE PROMOTED

Verification becomes THE product moat

Merge queue = one hardening item among eight→verification is arco's differentiating layer, phased: diff-gate (live) → reuse the repo's own CI as the test leg → in-daemon rebase→test→merge queue emitting a proof artifact

Source-verified: nobody on herdr closes the loop between "agent says done" and "work is actually done". Verified 2026: nothing light and self-hostable exists to buy (bors-ng dead, GitHub MQ needs org repos).

IN PLAIN WORDS"Done" stops meaning "the agent said so" and starts meaning "the branch rebased, the tests passed, here's the proof." This is the one thing no competitor does.
H1→H2
D5 — BRAIN CHANGED

Brain suggests; you decide — for a long time

Push brain quality toward auto-answering→brain = classifier + shadow drafter only; auto-mode is gated on D4 verification being live; borrow hap's MIT-licensed LLM plumbing (MCP get_context/submit_decision)

Still fixes the HIGH finding (feed facts/summary/memory into the prompt), enforces stall_n, and exposes the brain's rationale in escalations. But hap's answering loop is a month ahead and it's their whole product — we don't fight their strength.

IN PLAIN WORDSThe brain writes a suggested answer under every escalation on your phone; you tap or override. It only gets to act alone once the receipts system can catch its mistakes — because an idle agent is recoverable, a misdirected one burns a day.
H1
D6 — OPERATOR CHANGED

Phone decision cards ARE the product

status/logs/webhook as niceties; Telegram + web dashboard as add-ons→ntfy push cards (context + draft + one-tap answer) as the primary interface; arco status CLI; web dashboard KILLED

Implementation: the shoutrrr Go lib → self-hosted ntfy (real iOS/Android push). One dependency deletes both the bespoke webhook code and the entire Telegram roadmap item. collie/herdr-remote own the visual remote surface — arco won't rebuild it.

IN PLAIN WORDSAway from home, arco's entire face is a phone notification you can answer with one tap. At home, its face is herdr itself plus one CLI command. No web app to build or maintain.
H2
D7 — SECRETS CHANGED

Yes, a secrets manager — the one systemd already ships

Bespoke tmpfs file now, custom credential socket later→systemd-creds / LoadCredential= for arco's own secrets; keep the per-spawn tmpfs handoff for agents (it already matches systemd's model)

Secrets arrive as files in /run/credentials/arco.service/ — never in argv or env, encrypted at rest, TPM-bindable, ~0 lines of Go. Fixes the MED-5 argv leak at the root. OpenBao/Infisical verified alive but rejected: another daemon to babysit.

IN PLAIN WORDSNo token ever shows up in ps output or a process environment again — and we get that by using what's already installed, not by running a vault service.
H1
D8 — DEBT KEPT +2

Close the drift

Three missing §E tests; kill-9 crash matrix; wire stall_n, delete the other dead knobs; quota-policy contingency. New additions: competitive teardown updated for hap + Gas City + Auto Mode, and adopt hap's idea of a CI-validated "never-auto" safety-regex corpus.

IN PLAIN WORDSPay down the small known lies in the codebase (config options that do nothing), and keep the competitor analysis honest now that we know who the competitors actually are.
H1
D9 — COEXISTENCE NEW

When you're at the keyboard, arco gets out of the way

Born from your "support tool" requirement: manual herdr at home must never fight arco. Per-session mode auto | assist | manual — manual: arco watches and records but never acts or pings; assist: notifies + drafts, never acts; auto: earned (D5 gate). Source-verified back-off signals: herdr exposes no "human is typing" API, but three reliable proxies exist — focus-change events arco didn't cause, done→idle status flips (only human viewing triggers those), and scrollback movement (only humans scroll). Any of them starts a "human is active" timer that drops auto → assist. Two hard rules from the source read: arco never calls pane.focus in auto mode (it would fake herdr's "seen" flag), and since arco's keystrokes are indistinguishable from yours at the terminal level, every ledger entry records who answered — you or arco.

IN PLAIN WORDSSit down at your laptop and start driving — arco notices within seconds and automatically demotes itself to "suggest only". Walk away, and it resumes. And you can always check the ledger to see which answers were yours and which were the machine's.

The cut list — what rev-7 removes −⅓ of remaining surface

Red-team verdict: as-scoped, rev-6 was a 10× overbuild for "3 VMs, phone, away-mode" — and scope is what makes the two-upstream treadmill (Claude Code weekly, herdr 0.x) unsustainable solo. Cut:

  • Web dashboard, attach, session-detail UI — collie / herdr-remote / herdr own visual surfaces
  • Session trees, supersession, depth-2 — scaffolding for a fleet size that doesn't exist
  • Memory tiers 3–4 (revisions, playbooks) — tiers 1–2 (facts, context summary) suffice for the brain fix
  • Provider pools beyond one static pool — single-operator homelab
  • Telegram forum UX — replaced by ntfy cards (D6)
  • Bespoke sandbox + own hook layer — replaced by srt (D2) and herdr events (D1)
  • P3 "swarm" ambition — demoted to "3 known VMs over Tailscale"; the validated SSH layer covers it

Frozen §B schema keeps the unused tables — harmless, no migration needed.
